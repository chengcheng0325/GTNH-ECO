# 网友建议研究报告（t117，只研究不改代码）

> 来源：网友多段建议（升级/结构/配置界面/任务线/参考 mod）；调研对象：本 mod 升级系统现状、
> Science Not Leisure（sciencenotleisure，本地 290 版 0.2.7-pre1 / 下载 0.2.6）、高版本 ECO 源码、
> 既有 TST/ae2fc 调研结论。

## 一、建议拆解（7 条）

1. **升级和直接塞入并行**——升级/直塞盘不冲突（应指：升级树解锁的容量/种类与直接插盘并存）。
2. **小节点太多**——升级树小节点过多；建议磁盘相关单独整合，**按结构数量提供上限、每种单独调节**；剩余关键节点做成任务线。
3. **可视化配置界面**——材料自动配置替换，类似高版本 ECO 但更智能；高低版本现在都只能手塞磁盘。
4. **重要节点 = 机器内提供材料解锁**——类似"神锻"（Godforge）/ Science Not Leisure 的机器内材料升级。
5. **关键节点做成任务**（做不做是玩家的事）——存储物品/种类数量、源质创造升级、合成 CPU 无限数量、并行。
6. **参考实现**：SNL 压缩机/电聚爆等机器内材料升级（1-2 次）；GTO 多方块存储器（结构内特定方块达标 + 加材料自动解锁）。
7. **终局形态**：一台全满宇宙盘 = 无限存储（物品/流体/源质均匀塞三种宇宙盘）；CPU 一台全满宇宙 CPU 盘；合成器同样——造价弥补强度。

## 三、逐条可行性分析

### 1. 升级与直塞并行 ✅ 现状已基本成立
升级树解锁的是"可用容量/类型/档位门槛"（节点门控），盘始终是直接插入驱动槽——两者本来就是并行的。无需改动；若网友指"升级面板里同时能插盘"，那是 GUI 集成问题（低优先）。

### 2. 小节点整合 + 结构数量上限 ⚠️ 可行，但要重新设计门控模型
- 现状 26 节点确实偏多、单个节点收益小。
- 建议方向：**磁盘侧（字节池 N1-N9）改成"结构数量驱动"**——比如按驱动槽数量/盘位数量提供容量上限（每增加 1 个结构单元 → 上限 +X），移除 N 系节点；种类限制（物品/流体/源质）各自单独一条调节线。
- 工作量：中等偏大。涉及 UpgradeTree/UpgradeTreeGui/门控逻辑重写；存档兼容（已有节点激活状态迁移）。
- 收益：节点数大减（26 → 10 以内），逻辑直观。

### 3. 可视化配置界面（材料自动配置替换）⚠️ 可行，工程量最大
- "类似高版本 ECO 更智能"：高版本 ECO 其实没有复杂配置界面（只有盘级别枚举 + 控制器 GUI）；网友的想象更接近"自动把库存材料填入升级"。
- 可实现形态：**升级界面增加"一键填充材料"**（从 AE 网络/背包自动取所需材料放入升级消耗）、**批量升级**（一键升到目标节点，自动扣材料）。
- 技术上：MUI 已有界面基础 + AE 网络提取逻辑（我们已有 cell 访问代码）——可行；工作量中等。
- "更智能"（自动替换、推荐路径）属于体验层，可后置。

### 4. 机器内提供材料解锁（SNL/神锻式）✅ 可行，推荐核心形态
- SNL 事实（本地 0.2.7-pre1 反编译）：机器是 TecTech 系（TTMultiblockBase），自带 **BetterQuesting 任务线**（assets/sciencenotleisure/quest/QuestLines）；机器升级是"低次数"的（网友说 1-2 次）。
- 神锻（Godforge）模式 = 机器槽位内放材料 → 解锁/升级功能（TST 分析时见过 godforge 配方体系）。
- **对我们的落地**：升级节点改为"机器内升级仓/槽"——把材料放进主机/升级仓，点确认消耗材料解锁节点（替代现在的"材料从哪来"？——现在升级怎么消耗材料？查：节点激活消耗材料库存/背包）。本质 = 升级交互从"树点节点"改为"机器内放材料+确认"，后台逻辑可复用。
- 工作量：中；GUI 改造 + 材料消耗逻辑（现有 UpgradeCosts 可复用）。

### 5. 关键节点做成任务线 ⚠️ 依赖 BetterQuesting（GTNH 自带），可行但侵入大
- SNL 用 BQ 任务线承载机器引导。GTNH 整合包自带 BetterQuesting，我们的 mod 可以注册任务线（BQ API/JSON）。
- 但任务 = 玩家可选引导，**不能作为硬门控**（BQ 任务可被绕过/自定义）——只能作为"提示/奖励"层；硬门控仍留在升级树/机器内。
- 推荐：把"关键节点"（源质创造、CPU 无限、并行上限）做成**机器内升级（4）+ 可选 BQ 引导任务**双轨。

### 6. GTO 多方块存储器（结构方块达标 + 材料解锁）⚠️ 概念可借鉴，GTO 本体待确认
- 网友的"GTO"未在本地找到对应 mod（可能是 GT++ 或某社区 mod 的多方块存储），建议向网友要 mod 名/截图再深挖。
- 概念（结构内特定方块数量达标 → 解锁上限）与建议 2 的"结构数量驱动上限"同源——**可以合并实现**：驱动槽/盘位数量 = 结构计数，达标自动提升上限（不耗材料），材料只用于"种类/特殊功能"解锁。

### 7. 终局形态：一台全满宇宙盘 = 无限存储 ✅ 设计可行，平衡由造价决定
- 物品/流体/源质三种宇宙盘均匀塞一台（全满 = 12 驱动槽 3×4？），CPU 一台全满宇宙 CPU 盘——与现有"宇宙盘 MK-III 太空组装配方 + 升级树上限"兼容；关键是**升级树/里程碑让上限最终放开到"一台全满"**（现在 N 系节点是否允许？）。
- 造价强度比：宇宙盘配方极贵（UXV 太空组装），自然平衡——网友自己也认可"造价弥补强度"。
- 需要注意：**无限存储的并发/性能**（字节池 Long.MAX_VALUE 路径已有；网格 I/O 压力参考 AE2 wiki 建议）。

## 四、推荐路线（如果要落地，分 3 阶段）

| 阶段 | 内容 | 工作量 |
|---|---|---|
| P1（体验） | 升级界面"一键填充/批量升级"材料自动配置；节点合并小节点（26 → ~10） | 中 |
| P2（结构驱动） | 磁盘容量上限改为结构数量驱动（驱动槽/盘位计数），移除 N 系小节点；种类上限单独调节 | 中 |
| P3（机器内升级） | 关键节点（源质创造/CPU 无限/并行）改机器内材料解锁（复用 UpgradeCosts）；可选 BQ 引导任务线 | 中-大 |

P1 独立可做；P2 需存档迁移设计；P3 依赖 P1/P2 的节点重构。
